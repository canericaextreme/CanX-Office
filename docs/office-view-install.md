# Office view service — install and setup

Approved by John 10 Oct 2026. **Important:** the Office's database and edge functions live in a separate Supabase project (ref `gmsjjiprtulxojhkmbqb`). Lovable's database connector reports "not enabled" for it, so merging code to `main` never runs migrations or deploys Supabase functions. Those two steps require a separate Supabase deployment; they can be done by an authorised assistant with Supabase access. Until step 4 the viewing tools do not exist, and until step 5 no assistant can view anything.

Single-file copies of both functions are generated by `node scripts/office-view/bundle-functions.mjs <folder>` (needs `esbuild`); the bundle is smoke-tested (loads, refuses unauthenticated calls).

## Steps (deployment can be performed through the Supabase connector; owner authorisation remains personal)
1. **Database** — Supabase dashboard → SQL editor → new query → paste all of `supabase/migrations/20261011012433_office_view_delegation.sql` → Run. Use the Supabase migration tool for a recorded, transactional installation (all or nothing). Check: reload Build & Testing; the "Assistant viewing access" panel should show Claude, ChatGPT and Elsie as OFF with no "not installed" warning. Undo: drop `canx_private.office_view_*`, the `canx_view_*` functions and the `office_view_read` policies.
2. **Viewing accounts** — Authentication → Users → Add user, three times (Claude, ChatGPT, Elsie): any address you control that is not your owner address (a plus-address works; no email is sent), a long random password you do not keep, "Auto confirm" on. Do **not** give them any role. Keep only their user ids.
3. **Edge function `office-view`** — Edge Functions → Deploy a new function, name `office-view`, paste `office-view.js`, **turn "Verify JWT" OFF** (the capture workflow proves itself with GitHub's token, and assistant tokens are checked in the code). Secret `CANX_VIEW_DISPATCH_TOKEN` = a GitHub fine-grained token for this repository only with Actions: read and write, expiry 90 days. Never paste the token in chat. Undo: delete the function and the token.
4. **Turn on the tools** — redeploy `office-mcp` with the new `office-mcp.js` (keep its existing JWT setting), then set the secret `CANX_VIEW_SERVICE_URL` = `https://gmsjjiprtulxojhkmbqb.supabase.co/functions/v1/office-view`. Undo: remove that secret; the tools disappear.
5. **Authorise** — Build & Testing → Assistant viewing access → pick assistant, paste its user id, choose rooms and scope, enter your authenticator code once. Undo: "Switch off" (no authenticator needed).

The capture workflow (`.github/workflows/office-view-capture.yml`) is already in the repository. It uses the broker address above unless the repository variable `CANX_VIEW_BROKER_URL` overrides it.

## Retention
Pictures past 24 hours or revoked are unreachable at once (the database refuses them). The authenticated `office-view-cleanup.yml` workflow retries physical deletion hourly. Deletion is acknowledged in the database only after Storage confirms success. Failed runs remain visible in GitHub Actions. GitHub schedules can be delayed; physical deletion is not guaranteed at the exact 24-hour instant.

## Cost
No new paid service. GitHub Actions is free on a public repository (about 1–2 minutes per capture). Storage: PNGs ≤3 MB, inaccessible after 24 hours and queued for hourly deletion. Usage still counts against existing Supabase quotas; no new paid service is introduced.

## Known limits (do not claim otherwise)
- Unclassified notes are withheld; only explicitly shared notes or recognised room sources are readable. Work Board, Approvals and Build & Testing records require their respective room grants. The complete Finance document requires Finance access, including when a Subscriptions or Communications view uses that document.
- `read_room_information` returns only the requested room's rows (database function `canx_view_room_information`, run as the viewer, so row-level security applies). Device-only data is never included.
- A capture takes roughly 30–90 s (workflow start-up).
- Elsie's path relies on John's signed-in session for her conversation and is text-only until an image is proven to reach her.
- Nothing here has run live. Stand-in success is not live verification.
